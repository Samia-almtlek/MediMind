# Firebase Setup & Configuration – MediMind

## 1. Purpose of this document
This document explains how Firebase is configured in the MediMind project.
It is meant to help any team member continue development without breaking the Firebase setup.

---

## 2. Firebase Project Information
- Project name: MediMind
- Firebase Project ID: medimind-750fe

IMPORTANT:
- Do NOT create a new Firebase project.
- All development must use this existing project.

---

## 3. Tools & Technologies
- Flutter (Dart)
- Firebase
  - Firebase Authentication
  - Cloud Firestore (database)
  - Cloud Storage (optional)
- FlutterFire CLI

---

## 4. How Firebase is connected to Flutter
Firebase was connected using the FlutterFire CLI.

Command used:
flutterfire configure

This generated the file:
lib/firebase_options.dart

IMPORTANT RULES:
- Do NOT edit firebase_options.dart
- Do NOT delete it
- This file is auto-generated by FlutterFire

---

## 5. Firebase initialization in the app
Firebase is initialized in main.dart using:

await Firebase.initializeApp(
  options: DefaultFirebaseOptions.currentPlatform,
);

This ensures the correct Firebase configuration is used for each platform.

---

## 6. Android configuration notes
- Kotlin DSL is used (build.gradle.kts)
- The google-services Gradle plugin is NOT used
- Firebase is fully handled via FlutterFire

IMPORTANT:
- Do NOT manually modify Gradle files to add Firebase logic.

## 9. Firestore Security Rules
Firestore rules must:
- Require authentication
- Allow users to access only their own data

IMPORTANT:
- Firestore must NOT remain in test mode for production.

## 10. What must NOT be changed
- Firebase Project ID
- firebase_options.dart
- Firebase initialization logic

Changing any of these may break the entire application.
